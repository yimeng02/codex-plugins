# 0.2.1：精确匹配与插件标识匹配可选

编辑记忆或导出规则时，先选择“匹配方式”。

| 匹配方式 | 适用范围 | 保存与检索 |
| --- | --- | --- |
| 精确匹配（默认） | 全局、项目、技能、插件 | 保留原行为，按作用域和目标文本原值匹配；全局目标为空 |
| 插件标识匹配 | 插件 | 从本机缓存列表选择或手动填写准确插件 ID，独立使用 `plugin_id`，不使用目标文本 |

即使精确目标文本恰好与插件 ID 相同，两种匹配也不会相互命中。切换方式前填写的草稿会在编辑器中保留，保存时仅提交当前方式。旧记忆默认精确匹配，升级不会转换目标或产生条目历史版本。

## 在 Codex 中使用

精确匹配：

```json
{"scope":"plugin","target":"Android Engineering Ops"}
```

插件标识匹配：

```json
{"scope":"plugin","plugin_id":"android-engineering-ops"}
```

以上参数可用于 `memory_search`。`memory_refresh` 使用 `contexts` 数组传入这些对象，并始终读取启用的全局记忆。需要两种方式时分别提供两个 context，不把显示名猜测为 ID。

新增或修改条目时，插件标识模式使用 `match_mode="plugin_id"`、`scope="plugin"`、`plugin_id`，且 `target=""`；精确模式使用 `match_mode="exact"` 和原目标。`memory_render` 与 CLI publish 同样接受匹配方式。旧导入文件和旧历史版本仍默认为精确匹配。新导出格式为 schema_version=2，新版可导入 1/2 两种格式；包含新字段的文件需使用新版插件导入。

## 更新提醒与首次使用确认

网页保存后提示到 Codex 调用 `memory_refresh` 重新读取；`memory_status` 也会返回更新提醒，已完成首次配置的用户仍可获取该提醒。复制指令不算读取，最近一次读取也不代表所有聊天已同步。状态轮询不会覆盖编辑草稿。

首次在 **Codex 聊天中实际使用插件** 时，先说明本机资料库、两种匹配方式、记忆更新后的读取步骤、个人市场更新插件的方法，以及加入/暂不加入/稍后三种选择，再预览实际全局文件路径并询问是否加入读取规则：

完整正文见[全局读取规则与更新方法](GLOBAL-RULE.md)。规则覆盖任务读取、两种匹配方式、记忆更新后刷新、插件升级和全局规则更新，替代原三行简版。

仅在用户明确同意后写入，保留其他内容并备份；用户可选择暂不加入或稍后。未回答不写入，同一聊天不重复询问。询问发生在 Codex 内，网页不提供写入全局 AGENTS 的按钮。

## 更新方式

在 Yimeng02 个人市场更新“规则与记忆管理器”，或运行：

```text
codex plugin marketplace upgrade yimeng02
codex plugin add codex-memory-manager@yimeng02
```

完全退出并重启 Codex，在本地新聊天使用新版插件；重启管理页面进程后加载新网页和 API。沿用原记忆数据库。0.2.0 的更新提醒与首次使用确认详见[原版说明](RELEASE-0.2.0.md)。
