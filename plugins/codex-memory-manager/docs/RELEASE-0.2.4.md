# 0.2.4：移除新增的插件标识匹配

记忆统一使用原有的精确匹配：保存什么 scope 和 target，就按该原值检索。插件的显示名称和标识可以作为普通目标文本，但不会相互转换、模糊匹配或另开匹配分支。

- 网页编辑器与 Markdown 导出移除“匹配方式”、插件标识输入和插件选择器，保留关联目标。
- MCP 新增、编辑、搜索、刷新与渲染接口移除 match_mode / plugin_id 参数；CLI publish 移除对应选项。旧调用会明确报错，不会忽略条件后返回更大范围。
- 新聊天、恢复和压缩后的全局记忆自动读取，以及资料库更新后的刷新保持可用。钩子定义未变，已有信任沿用。
- 既有精确匹配条目保留目标、正文、版本和历史，不批量迁移。旧资料库内部列保留以兼容先前版本。

旧格式条目仍可读取：旧 plugin_id 作为普通关联目标呈现，原始数据库行与历史快照不因打开或检索而重写。主动编辑、导入或恢复旧版本时按当前格式保存，旧历史仍保留。

新 JSON 导出版本为 schema_version=3，内容仅包含精确目标字段；导入兼容 1、2、3。旧版中同时包含不同 target 与 plugin_id 的歧义条目会拒绝，不擅自选择目标。

从 Yimeng02 个人市场更新插件，完全退出并重启 Codex；正在运行的网页服务也需重启，浏览器刷新后显示新版选项。原资料库继续使用。

全局 AGENTS.md 中若仍包含旧匹配分支，先使用 memory_setup(action="preview") 查看新规则和差异，经用户明确同意后应用；本次插件升级不会直接改写该文件。
