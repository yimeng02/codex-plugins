# 0.2.0：插件目标选择、更新提醒与 Codex 首次使用

## 插件标识可选

记忆编辑器选择“插件”范围后，可从“插件标识”选择本机发现的插件。选项同时显示名称与实际标识，例如 `Android Engineering Ops · android-engineering-ops`，保存的是实际标识。导出规则中同样可选。

目录来自本机插件缓存，发现不等于已启用。未缓存的插件可手动填写标识；原有显示名或未知目标保留原值，不会因打开编辑器自动改写。只有用户选择并保存后才更新。

## 网页提醒到 Codex 重新读取

网页顶部持续显示当前资料库版本与最近一次插件读取版本。库有更新时，提示在需要使用的 Codex 聊天中调用插件，按钮可复制重新读取指令。

在 Codex 中可直接说：

```text
使用 memory-manager，更新本聊天使用的记忆，读取全局和当前任务相关范围，并说明实际读取版本。
```

`memory_refresh` 总是读取启用的全局记忆，指定 `contexts` 时同时读取精确匹配的项目、技能或插件记忆。它返回其他范围的索引，以便根据实际任务继续检索。记录读取版本不会修改条目或产生新的库 revision。

复制指令不会清除更新提醒；插件读取完成后，网页约十秒内更新状态。这个状态仅记录最近一次插件读取，不代表所有聊天同时生效。状态轮询不会覆盖未保存的编辑草稿。

## 在 Codex 首次使用时询问

询问发生在 Codex 聊天实际使用插件时，网页不承担首次配置询问。初始化只提供首次使用指引，不会后台写文件。

首次状态为 `pending` 时，插件先预览，Codex 展示下面三行原文并询问是否加入全局 AGENTS：

```text
开始任务时，使用 memory-manager 读取全局启用记忆；
涉及具体项目、技能或插件时，按准确作用域和目标检索相关记忆。
仅应用与当前任务相关的内容；工具不可用时如实说明。
```

- 加入：用户明确同意后，`memory_setup` 以预览的 `path` 和 `sha256` 同时检查目标及原文，保留其他内容并备份，再写入独立受管区块；新聊天验证加载。
- 暂不加入：记录 `declined`，不写文件，后续不自动重复询问。
- 稍后：记录 `deferred`，不写文件，以后可主动要求重新配置。
- 尚未回答：不等于同意或拒绝；当前聊天不重复询问，仍可继续管理记忆。

若 `AGENTS.override.md` 当前生效，预览会指明该实际全局文件。网页接口不提供写入 AGENTS 的功能。该读取区块与旧版导出的记忆正文区块独立。

## 更新

在 Yimeng02 市场更新“规则与记忆管理器”，或运行：

```text
codex plugin marketplace upgrade yimeng02
codex plugin add codex-memory-manager@yimeng02
```

重启管理页面进程以加载新网页和 API；在 Codex 新聊天使用新版技能和工具。记忆数据库沿用原位置。已有用户升级后也会进行一次首次使用确认，原记忆条目保持原样。
