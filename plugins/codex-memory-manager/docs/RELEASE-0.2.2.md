# 0.2.2：新聊天自动读取修复

## 修复了什么

旧版把 memory_status / memory_refresh 写入全局 AGENTS，仍依赖模型主动调用。新聊天无论是问候还是具体任务，都可能因模型漏调用而未读取管理器里的全局偏好。

新版使用 Codex 原生插件清单 `.codex-plugin/plugin.json` 和官方生命周期钩子直接准备上下文，不经过模型工具选择，也不等待 MCP。当前客户端加载器会跳过便携 AgentPlugin 格式的钩子，因此 Codex 发行版不再放置会遮蔽原生清单的根 plugin.json。插件名称、市场来源和记忆库位置保持一致。

触发行为：

- **SessionStart**：启动、恢复、清空、压缩、派生聊天时重新准备启用的全局记忆。
- **UserPromptSubmit**：本聊天没有记录或库版本变化时重新准备；版本未变化则无额外上下文输出。
- 修改、启停、删除、恢复、导入记忆后，下一条用户消息读取新版本。空全局列表也会替换旧内容；停用和删除的旧 ID 会列为撤销。
- 项目、技能和插件只提供准确目标索引，不把全部正文自动注入。原精确匹配和插件标识匹配保持独立。

## 启用

1. 在 Yimeng02 市场更新到 0.2.2，完全退出并重启 Codex。
2. 根据客户端提示审核本插件的两个钩子；CLI 可使用 `/hooks` 查看并信任 `SessionStart` 和 `UserPromptSubmit`。安装、启用插件不会自动授予信任，钩子定义变化后也需重新审核。
3. 在本地新聊天只发送“你好”，核对全局偏好。原有聊天可在恢复或下一条消息时获得钩子读取；无需打开 Codex 内置记忆。

钩子命令调用插件内的 hooks/memory_context.py，默认 POSIX 使用 python3，Windows 使用 py -3。本机安装器会绑定已选 Python 和自定义记忆目录，与 MCP 共用原资料库。不存在数据库时仅提示，不另建空库。无需更改全局 AGENTS 即可启用已信任钩子。

官方要求非托管钩子先审核、信任；安装器不会写 trusted_hash，也不会使用绕过信任的选项。企业策略若只允许托管钩子、客户端不支持本地钩子、或钩子未获信任，则自动读取不会运行，应明确提示并使用 MCP 手动读取。

## 核对实际版本

memory_status 仍返回资料库最近一次读取记录；新增可选参数 session_id 查询指定聊天的 session_context。

```text
python3 run.py tool memory_status --json '{"session_id":"实际聊天ID"}'
```

session_context 中的 revision / prepared_at 是“为该聊天准备给宿主”的记录，不能证明模型已经遵循。没有记录返回 null；needs_refresh 表示该准备记录落后于当前库版本。最多保留最近 1000 个聊天的操作记录，不进入记忆导出，不改变条目版本或库 revision。

自动上下文总量最多 18000 UTF-8 字节，按优先级保留完整条目，超出时报告 omitted_global_count，需按任务继续检索。不要把部分注入报告为完整加载。

## 数据与验证边界

钩子仅读取启用且未删除的全局条目，写入读取时间和按聊天准备记录；不修改条目、分类、历史、原生 Codex 记忆或 AGENTS，不保存提示词和聊天正文。资料库锁定等错误会提示，聊天继续运行。

新版全局规则模板可按需预览后另行确认更新；本修复不自动覆盖已写入的全局规则。

发布验证：Linux 全部 139 项测试通过；Windows Python 3.13 全部适用测试通过，5 项平台差异测试跳过。隔离配置中使用真实 Codex CLI 和本地模拟模型验证了两个原生插件钩子的发现、审核，以及首个模型请求包含全局记忆、排除其他范围正文。实际模型对偏好的执行仍需在目标客户端新聊天核对。
